# คู่มือต้นทุนและกำไรขั้นต้น — ข้อมูลทดสอบ v0.6.0

## เปิดบน Windows

1. ติดตั้ง Node.js **24 LTS** จาก https://nodejs.org เพียงครั้งแรก
2. ดาวน์โหลด branch `neeb20/prototype-demo` และแตก ZIP ออกก่อน อย่าเปิดโปรแกรมจากใน ZIP
3. เปิดระบบเดิมด้วย `START-NEEB20.cmd` หรือเปิดข้อมูลตัวอย่างแยกด้วย **`OPEN-PROFIT-DEMO.cmd`**
4. คงหน้าต่างคำสั่งไว้ ตัวอย่างกำไรเปิด Edge/Chrome ที่ **http://127.0.0.1:3002** หากไม่เปิดอัตโนมัติ ให้คัดลอก URL นี้หลังมีข้อความเซิร์ฟเวอร์พร้อมแล้ว
5. เลือก **ผู้จัดการทดสอบ 01** → เมนู **ต้นทุน / กำไร** → ตั้งรูปแบบสรุปรายได้เป็น **ย้อนหลังทั้งหมด**

ไม่ต้อง npm install สำหรับการใช้งานแอป การดับเบิลคลิก helper ตัวอย่างซ้ำไม่เติมยอดตัวอย่างเพิ่ม ฐานเดิม `.data/demo.sqlite` และฐานกระทบยอด `.data/reconciliation-sample.sqlite` ไม่ถูกแทนที่ หากพอร์ตถูกใช้ ให้ปิดเซิร์ฟเวอร์เก่าก่อนเปิดใหม่ อย่าลบฐานข้อมูลเพื่อแก้ปัญหาเปิดเว็บ

ทางเลือก PowerShell เปิดตัวอย่างครั้งแรก:

```powershell
node scripts/seed-profit-demo.js
$env:NEEB20_DEMO_DB="$PWD\.data\profit-sample.sqlite"
$env:PORT=3002
npm start
```

script สร้างตัวอย่างจะปฏิเสธการทับไฟล์เดิม คำสั่งเปิดเซิร์ฟเวอร์ใช้ฐานเดิมได้ ไม่ต้อง seed ซ้ำ

## สูตรและการเก็บข้อมูล

- หน่วยในบัญชีและต้นทุนบริการ: จำนวนเต็มสตางค์ คำนวณเปอร์เซ็นต์เฉพาะแสดงผล
- กำไรต่อหน่วยสินค้า = ราคาขาย − ราคาทุน อัตรากำไร = กำไร ÷ ราคาขาย × 100 ไม่ใช่อัตราบวกจากทุน
- ต้นทุนบริการประมาณการ = วัสดุ + ไฟ + น้ำ + ค่าแรง + อื่น ๆ **ค่าแรงรวมส่วนค่าคอมประมาณการแล้ว** ช่องค่าคอมที่รวมในค่าแรงเป็นส่วนอธิบาย ไม่บวกเพิ่ม
- เมื่อทราบค่าคอมจริง: ต้นทุน = ต้นทุนเดิม − ส่วนค่าคอมที่รวมแล้ว + ค่าคอมจริง เช่น ค่าแรง 5 บาทรวมคอม 3 บาท ทุนรวม 7 บาท คอมจริง 4 บาท → ทุน 8 บาท ไม่ใช่ 11 บาท
- ต้นทุนจริงทั้งหมดแทนประมาณการได้ ต้องระบุส่วนค่าคอมที่รวมในค่าแรงใหม่ด้วย เพื่อคำนวณกับค่าคอมจริงล่าสุดให้ถูกต้อง การบันทึกค่าคอม 0 ต้องกรอกเลข 0 การเว้นว่างหมายถึงยังไม่ทราบ
- กำไรขั้นต้น = รายได้สุทธิรับเงินจริงหักคืนเงิน − ต้นทุนที่เกี่ยวข้อง อัตรากำไรขั้นต้น = กำไรขั้นต้น ÷ รายได้สุทธิ × 100 ถ้ารายได้สุทธิเป็นศูนย์หรือติดลบแสดงเปอร์เซ็นต์ “—” เพื่อไม่หารศูนย์
- รายงานแยกสินค้า บริการ และรวม ถ้ามีต้นทุนขาดในกลุ่ม จะแสดงเฉพาะต้นทุนที่ทราบ พร้อมสถานะไม่ครบ **ไม่แสดงกำไรรวมที่อาจสูงเกินจริง**

สินค้าในบิลล็อกราคาขายตอนเพิ่มรายการ แต่ต้นทุนขายล็อกใน transaction เมื่อยืนยันรับเงิน ราคาทุนที่เปลี่ยนระหว่างเปิดบิลจึงใช้ค่าล่าสุดตอนขาย เมื่อขายแล้วจะไม่แก้ snapshot บริการล็อกราคาและต้นทุนประมาณการตอนสร้างรายการเริ่มคิว/ต่อเวลา การแก้ catalog ส่งผลต่อรายการใหม่เท่านั้น ไม่เปลี่ยนเวลาสิ้นสุดหรือ 25/5 นาที

ค่าบริการเริ่มต้นในระบบเดิมยังคง 20 บาท และต่อเวลา 5 บาท ผู้จัดการสามารถเปลี่ยนราคาใน catalog ได้ ป้าย Station จะแสดงราคาปัจจุบัน รองรับต้นทุน catalog สระ100 แต่รุ่นนี้ยังไม่เพิ่มระบบจอง/ขายสระ100 หรือบริการแบบอิสระ

## ตัวอย่างตรวจสูตร

ฐานตัวอย่างมีคิวชำระแล้ว 1 คิว:

| รายการ | รายได้ | ต้นทุน |
|---|---:|---:|
| หนีบ20 | 20 | 8 (ประมาณการเดิม 7 แทนคอม 3 ด้วยคอมจริง 4) |
| ต่อเวลา | 5 | 1 |
| หวี | 29 | 15 |
| รวม | **54** | **24** |

กำไรสินค้า 14 บาท กำไรบริการ 16 บาท รวม 30 บาท อัตรากำไร 30 ÷ 54 × 100 = 55.56%

ลองตรวจสอบ:

1. แก้ราคาทุนหวีเป็น 18 บาท ขายเป็น 35 บาท และแก้ต้นทุนบริการ ยอดคิวเดิมต้องยังเป็น 54 บาท ทุนเดิม 24 บาท กำไร 30 บาท
2. บันทึกค่าคอมจริงของรายการหนีบ20 เดิมเป็น 5 บาท พร้อมเหตุผล ทุนบริการเพิ่ม 1 บาท กำไรรวมเหลือ 29 บาท รายการรับเงินและสต๊อกไม่เปลี่ยน ประวัติค่าคอมทั้งสองครั้งคงอยู่
3. เลือกวัน/สัปดาห์/เดือน/ช่วงวันที่ครอบคลุมตัวอย่าง ผลรวมต้องตรงกัน ส่งออกกำไร CSV ตรวจ reference ต่อรายการได้ รีเฟรชและหยุด/เปิดเซิร์ฟเวอร์ใหม่ ข้อมูลยังอยู่
4. เปลี่ยนเป็นพนักงานทั่วไป หน้าต้นทุน กำไร และราคาทุนต้องไม่แสดง API staff ไม่ส่ง snapshot ต้นทุน ประวัติต้นทุน สำเนาข้อมูลเก่า หรือ fingerprint ของคำสั่งที่มีต้นทุน
5. ทดลองเริ่มคิวใหม่ ยังไม่ชำระ ย้ายจุด ต่อเวลา หรือจบคิวเดิมที่ชำระแล้ว รายรับต้องไม่เพิ่มเพราะการย้าย/จบ ยอดเปิดบิลไม่เข้าเป็นกำไรจากขาย

## คืนสินค้า คืนเงิน ยกเลิก และข้อมูลย้อนหลัง

- คืนสินค้ากลับเข้าสต๊อก: คืนรายได้และย้อนต้นทุนตามจำนวนที่คืน ใช้ **ทุน snapshot ของการขายเดิม** ไม่ใช้ทุน catalog วันนี้
- คืนเงินโดยไม่รับสินค้ากลับ: ลดรายได้ แต่ต้นทุนสินค้ายังเกิดขึ้น กำไรอาจติดลบ
- คืนเงินบริการ: ลดรายได้ตามวันคืน ไม่สมมติว่าต้นทุนวัสดุ/แรงงานหายไปด้วย หากยังไม่ได้ใช้บริการจริง ให้ผู้จัดการบันทึกต้นทุนจริง 0 และค่าคอมจริง 0 พร้อมเหตุผล/หลักฐาน ไม่ลบรายการรับเงินและคืนเงิน
- ยกเลิกก่อนชำระ: ไม่มีรายรับ หากมีต้นทุนที่เกิดจริง ให้บันทึกต้นทุนจริง ระบบแสดงเป็นต้นทุนบริการยกเลิก/ขาดทุนตามวันที่บันทึกต้นทุนจริง ไม่เดาต้นทุนจากคิวที่กดผิดหรือบิลค้าง
- รายการคืนเงินรับรู้ในช่วงวันที่คืน ต้นทุนสินค้าคืนสต๊อกรับรู้กลับในวันคืน รายงานวันคืนจึงอาจติดลบตามจริง
- การทราบค่าคอม/ต้นทุนบริการจริงภายหลัง **ปรับรายงานของงวดขายเดิมตามข้อมูลล่าสุด** โดยไม่แก้ transaction เดิม เก็บ adjustment พร้อมผู้ทำ เวลา เหตุผล รหัสคำสั่ง กำไรรายงานที่พิมพ์ก่อนทราบต้นทุนจริงอาจต่างจากที่สร้างใหม่ จึงมี generatedAt และบอกนโยบายไว้
- ประวัติเก่าที่ไม่มีทุนบริการต้องแสดงต้นทุนไม่ครบ ห้ามนำทุนปัจจุบันไปใส่ย้อนหลัง ต้องบันทึกต้นทุนจริงที่อ้างอิงรายการเดิมจากหลักฐาน

## โครงสร้างและสิทธิ์

SQLite ฝั่งเซิร์ฟเวอร์เก็บ catalog สินค้า/บริการ, charge/transaction snapshots, `catalogHistory`, `costAdjustments`, audit, idempotency และ revision แบบเดิม เพิ่มโครงสร้างใน schema 5 แบบ additive ด้วย `costSchema:1` โดยไม่เปลี่ยน transaction/audit เก่า โครงสร้าง `operatingExpenseCategories` (ค่าเช่า เงินเดือนประจำ อื่น ๆ) และ `operatingExpenses` แยกไว้สำหรับอนาคต **ยังไม่มีหน้าลงค่าใช้จ่ายหรือรายงานกำไรสุทธิ** ห้ามลงเงินเดือนประจำซ้ำในค่าแรงบริการและค่าใช้จ่ายดำเนินงาน

API `/api/profit` และคำสั่งต้นทุน/ค่าคอมต้องเป็น manager API `/api/state`, `/api/reports`, ผล POST และสำรองข้อมูลจะตัดต้นทุนทุกระดับเมื่อเป็น staff อย่างไรก็ตามตัวตนมาจาก Demo identity `X-NEEB20-Actor`/actorId ซึ่งผู้ใช้เปลี่ยนเองได้ **ยังไม่ใช่ authentication** ห้ามเปิด public server หรือใช้ข้อมูลต้นทุนจริงก่อนเพิ่มการล็อกอิน ผู้ใช้/สิทธิ์ที่เซิร์ฟเวอร์ตรวจจาก session และ HTTPS Local Demo เก็บข้อมูลใน localStorage ที่ผู้ใช้เครื่องอ่านได้ ไม่ใช่ระบบเก็บต้นทุนลับ
