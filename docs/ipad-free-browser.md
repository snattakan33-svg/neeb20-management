# ใช้หนีบ20 บน iPad เครื่องเดียว โดยไม่มีเซิร์ฟเวอร์หรือฐานข้อมูลแบบเสียเงิน

รุ่น v0.8.0 เพิ่ม **Browser Demo** เป็นเว็บ Static Site ที่ทำงานใน Safari ข้อมูลอยู่ใน IndexedDB ของ iPad ไม่ได้เก็บใน Render ไม่ต้องเปิดคอมทิ้งไว้ ไม่ได้เชื่อมธนาคารหรือรับเงินอัตโนมัติ บทบาทผู้จัดการ/พนักงานยังเป็นการจำลอง ไม่ใช่ระบบล็อกอินจริง

## แบบที่เตรียมให้

- Render ให้บริการเฉพาะไฟล์เว็บแบบ **Static Site** ใช้ HTTPS และโดเมนย่อยของ Render ไม่ต้องซื้อโดเมน
- ไม่ใช้ Render Web Service ที่รัน Node, ไม่ใช้ persistent disk, PostgreSQL, D1 หรือบริการฐานข้อมูลออนไลน์ใด ๆ
- Static Site ไม่มีการส่งบิล สินค้า สต๊อก หรือรายได้ไปเซิร์ฟเวอร์ แอปนี้ไม่มี analytics
- เว็บใช้ Station 12 จุด Timer POS SKU ต้นทุน กำไร และรายงานเดิม เปลี่ยนเฉพาะแหล่งบันทึกเป็น IndexedDB บนเบราว์เซอร์
- โหลดเว็บสำเร็จครั้งแรกแล้วเตรียม app shell แบบออฟไลน์ เพื่อใช้จากหน้าจอโฮมได้โดยไม่ต้องต่อเซิร์ฟเวอร์ บิลและรูปที่อัปโหลดเก็บบนเครื่อง ส่วนรูปที่เป็นลิงก์ภายนอกอาจไม่แสดงเมื่อออฟไลน์

**โครงการนี้ยังไม่ได้ถูกเผยแพร่ในบัญชี Render ของคุณ และยังไม่มี URL ใช้งานจริง** ต้องทำขั้นตอนสร้าง Static Site ด้านล่างในบัญชีของคุณก่อน ผู้พัฒนาไม่ได้สมัครบริการหรือเปิดแผนเสียเงินให้

## สร้างลิงก์เว็บฟรีจาก iPad (ไม่ต้องเปิดคอม)

1. เปิด https://dashboard.render.com ใน Safari สมัคร/เข้าสู่ระบบผ่าน GitHub ที่มี repository `snattakan33-svg/neeb20-management`
2. กด **New + → Static Site** อย่าเลือก Web Service, PostgreSQL หรือ Disk
3. เชื่อม GitHub และอนุญาตเฉพาะ repository `neeb20-management` ตามที่จำเป็น Repository ยังเป็น Private ได้ ไม่ต้องเปลี่ยนเป็น Public
4. เลือก repository นี้ กำหนด:

| ช่อง | ค่า |
|---|---|
| Name | `neeb20-ipad` หรือชื่อว่างอื่น |
| Branch | `neeb20/prototype-demo` |
| Root Directory | เว้นว่าง |
| Build Command | `node scripts/build-static.js` |
| Publish Directory | `static-site` |

5. ตรวจว่าประเภทเป็น **Static Site** และหน้า Dashboard ระบุ Free ตามเงื่อนไขบัญชีปัจจุบันก่อนกดสร้าง ไม่เลือกแผนเสียเงิน ไม่เปิดส่วนเสริม ไม่ผูกบัตรให้บริการเสียเงิน หากหน้าใดแสดงราคา ให้หยุดและตรวจสอบก่อน เพราะต้องการใช้แบบฟรีเท่านั้น
6. กด **Create Static Site** รอ build/deploy สำเร็จ แล้วเปิด URL `https://<ชื่อที่ได้รับ>.onrender.com` ที่ Render แสดง ชื่อจริงอาจไม่ใช่ `neeb20-ipad` หากมีคนใช้แล้ว
7. ถ้าใช้เมนู Blueprint แทนได้ มี `render.yaml` พร้อมค่า Static Site เดียวให้ตรวจสอบ โดยไม่มีฐานข้อมูลหรือดิสก์เสียเงิน

ค่าบริการและโควตาของผู้ให้บริการอาจเปลี่ยน ต้องดูหน้าแผนจริงในบัญชี Render ณ วันที่สมัคร โค้ดนี้ไม่ได้เปิดทรัพยากรเสียเงิน และไม่รับรองว่าโฮสต์ฟรีจะให้แบนด์วิดท์/พื้นที่ไม่จำกัด หากชนโควตาให้หยุดใช้บริการออนไลน์หรือเลือกโฮสต์ Static ฟรีอื่น ไม่อัปเกรดแผนโดยอัตโนมัติจากโค้ด

## เพิ่มไอคอนบนหน้าจอโฮมของ iPad

1. เปิดลิงก์ HTTPS ของ Render ใน **Safari โหมดปกติ** ไม่ใช่แท็บส่วนตัว ไม่เปิด HTML ผ่านแอป Files/Quick Look/WinRAR
2. กด **แชร์ → เพิ่มไปยังหน้าจอโฮม → เพิ่ม** (หากมีตัวเลือก Open as Web App ให้เปิด)
3. เปิดจากไอคอน **หนีบ20** และตรวจว่าเมนู **iPad / สำรองข้อมูล** ขึ้นว่า **พร้อมออฟไลน์แล้ว**
4. เริ่มเพิ่มสินค้า/ลงข้อมูลจากไอคอนนี้เป็นหลัก อย่าสลับหลายเบราว์เซอร์/หลายโปรไฟล์โดยคาดว่าข้อมูลจะเหมือนกัน
5. ก่อนใช้จริง ให้ทดลองเปิดโหมดเครื่องบิน เปิดเว็บจากไอคอนใหม่ เริ่มคิวทดสอบและรีเฟรช ตรวจว่าเวลาไม่เริ่มใหม่ แล้วกลับมาออนไลน์

Safari กับเว็บจากหน้าจอโฮมอาจใช้พื้นที่เก็บข้อมูลต่างกันตามรุ่น iPadOS หากเพิ่มไอคอนแล้วไม่พบข้อมูลที่เคยกรอกใน Safari ให้สำรองจากที่เดิม แล้วนำเข้าที่ไอคอนซึ่งยังไม่มีประวัติ ห้ามทดลองล้าง Safari เพื่อแก้ปัญหา

## สำรองทุกวัน

1. เลือกผู้จัดการทดสอบ แล้วกด **สำรองข้อมูลลงไฟล์** ด้านบน
2. บันทึก `.json` ลง **Files / iCloud Drive** หรือที่เก็บไฟล์อีกแห่งซึ่งไม่ใช่พื้นที่ข้อมูล Safari
3. ตรวจว่ามีไฟล์จริงและวัน/เวลาถูกต้อง การกดดาวน์โหลดแค่เตรียมไฟล์ ไม่ใช่หลักประกันว่าได้บันทึกลง iCloud สำเร็จแล้ว
4. สำรองอีกครั้งก่อนย้าย iPad เปลี่ยน URL/เบราว์เซอร์ ล้างข้อมูล Safari หรือนำเครื่องไปซ่อม

ไฟล์นำเข้ารองรับขนาดไม่เกิน 100 MB ในรุ่นต้นแบบนี้ หากไฟล์เริ่มใหญ่ควรตรวจสอบแผนจัดเก็บและการย้ายข้อมูลก่อนใช้งานต่อ

ไฟล์มีสินค้า รูป ต้นทุน บิล Session เวลาเริ่ม/สิ้นสุด ธุรกรรม ประวัติสต๊อก Audit และรหัสคำสั่งป้องกันยอดซ้ำครบ ไฟล์ไม่ได้เข้ารหัส จึงเก็บไว้ในที่ที่เจ้าของร้านเข้าถึงได้เท่านั้น ใช้ SHA-256 ตรวจความสมบูรณ์ ไม่ใช่ลายเซ็นดิจิทัลหรือระบบพิสูจน์ผู้สร้างไฟล์

## ย้ายข้อมูลจาก Windows หรือ iPad เดิม

1. เครื่องเก่าเลือกบทบาทผู้จัดการแล้วสำรอง JSON ทั้งชุด ไฟล์จากบทบาทพนักงานถูกตัดต้นทุน จึงใช้ย้ายฐานข้อมูลไม่ได้
2. ย้ายไฟล์ไป Files/iCloud Drive ของ iPad
3. เปิดลิงก์บน iPad/ไอคอนใหม่ที่ **ยังไม่ได้เริ่มคิว ขายสินค้า หรือแก้ข้อมูล**
4. เลือกผู้จัดการ → เมนู iPad / สำรองข้อมูล → นำเข้าไฟล์สำรอง → เลือกไฟล์ กรอกเหตุผล และยืนยัน
5. ระบบตรวจข้อมูลและ hash เก็บประวัติเดิม และเพิ่ม Audit เหตุการณ์นำเข้า ไม่สร้างยอดขายใหม่ ไม่รีเซ็ตเวลา Session

**ไม่อนุญาตนำเข้าทับเครื่องที่มีประวัติ** เพื่อไม่ให้บิลหรือยอดใหม่หลังวันสำรองหาย ไม่รวมฐานข้อมูลสองเครื่องเข้าด้วยกัน หากเครื่องปลายทางมีข้อมูลอยู่แล้ว ให้สำรองทั้งสองไฟล์และตรวจสอบก่อน อย่าล้างข้อมูลเพื่อฝืนให้ระบบรับไฟล์

## สิ่งที่ต้องเข้าใจ

- ข้อมูลแยกตามเครื่อง เบราว์เซอร์ โปรไฟล์ และ origin/URL ไม่ซิงก์ข้าม iPad ไม่ใช่ฐานข้อมูลกลาง
- แม้ขอ `navigator.storage.persist()` แล้ว เบราว์เซอร์อาจไม่อนุญาตหรือยังลบข้อมูลเมื่อผู้ใช้สั่งได้ หากเครื่องหาย/พัง/ล้าง Safari ข้อมูลอาจหาย ต้องมีไฟล์สำรอง
- ไม่มีค่าใช้จ่ายจากโค้ด แต่ไม่รับรองโควตาฟรีของผู้ให้บริการตลอดไป และการไม่มีฐานกลางไม่เท่ากับมี cloud backup
- เวลาอ้างอิงนาฬิกาของ iPad ไม่ใช่เวลาเซิร์ฟเวอร์ ควรตั้งวันเวลาอัตโนมัติ Safari พักแอปได้ แต่เมื่อเปิดกลับมาระบบคำนวณจาก endsAt เดิม
- การเลือก manager ยังเปลี่ยนเองได้ ผู้ใช้เครื่องที่เข้าถึงเบราว์เซอร์/ไฟล์สามารถอ่านข้อมูลได้ เหมาะทดลอง/ใช้ส่วนตัวบนเครื่องที่ควบคุมได้ ไม่ใช่ระบบสิทธิ์สำหรับพนักงานหลายคน
- เมื่อพื้นที่เต็มหรือ IndexedDB เปิดไม่ได้ ระบบจะแจ้งข้อผิดพลาด ไม่ล้างฐาน ไม่ย้อนกลับไปสร้างยอดใหม่โดยอัตโนมัติ
- Service Worker เก็บเฉพาะไฟล์โปรแกรม ไม่เก็บฐานข้อมูล บิล ไฟล์สำรอง หรือ API อัปเดตใหม่รอจนปิดแท็บเก่า ไม่รีโหลดระหว่างรับเงินอัตโนมัติ

## เปิดตรวจบน Windows ก่อนเผยแพร่ (ไม่ใช่ขั้นตอนที่ต้องทำทุกวัน)

```powershell
npm run build:ipad
npm run preview:ipad
```

เปิด http://127.0.0.1:4173 บนคอมเพื่อตรวจ Browser Demo เท่านั้น localhost ของคอมไม่ใช่ลิงก์ออนไลน์สำหรับ iPad เมื่อเผยแพร่ Static Site แล้ว คอมปิดได้

## ผลทดสอบและข้อจำกัดการตรวจสอบ

- Node tests ครอบคลุมระบบเดิมและการสำรอง/ตรวจ hash/นำเข้า JSON เก่า/ปฏิเสธไฟล์พนักงานที่ต้นทุนไม่ครบ
- Browser test บน Chromium ขนาด iPad แบบ touch ผ่าน: เปิดออฟไลน์/รีโหลด Timer บิล 54 บาท ต่อเวลา สินค้า ตัดสต๊อก ไม่เรียก API ป้องกันสองแท็บเริ่ม Station เดียว ย้ายไฟล์ไปเบราว์เซอร์ใหม่ และปฏิเสธไฟล์เสีย/การทับประวัติ รวมจำลองพื้นที่เต็มแล้วข้อมูลเดิมไม่หาย
- ชุด Station/POS/SKU/รูป/รายงาน/ปิดกะเดิมยังทดสอบแยก
- **ยังไม่ได้ทดสอบ Safari/iPad จริงหรือ WebKit ในสภาพแวดล้อมนี้** การดาวน์โหลด WebKit ถูกเครือข่ายปฏิเสธ HTTP 403 ต้องทดลองบน iPad จริงตามรายการด้านบนก่อนวางใจข้อมูลสำคัญ

```powershell
npm test
npm run build:ipad
npm run test:ipad
```

Browser tests ต้องเตรียม Playwright/Chromium ก่อน หรือใช้ `NEEB20_TEST_WEBKIT=1` กับ WebKit ที่ติดตั้งได้ในเครื่องทดสอบอื่น ไม่มี dependency เหล่านี้ในการเปิดเว็บจริง
