# หนีบ20 — NEEB20 Management System

ต้นแบบ Responsive Web App ภาษาไทยสำหรับร้านทำผมบริการตัวเอง **ใช้ข้อมูลทดสอบเท่านั้น** ยังไม่พร้อมใช้รับเงินจริง ไม่มีการเชื่อมระบบไฟฟ้าหรือคลังสินค้าจริง

## เปิดบน Windows / คอมพิวเตอร์

ติดตั้ง Node.js 22 ขึ้นไป (แนะนำรุ่น LTS) เปิด PowerShell ในโฟลเดอร์โครงการ:

```powershell
npm start
```

เปิดเบราว์เซอร์ที่ `http://localhost:3000` ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม ไม่มี dependency ภายนอก กด Ctrl+C เพื่อหยุด หากพอร์ตชน ใช้ `$env:PORT=3001` แล้ว `npm start`

ทดสอบบน iPad: ใช้ Wi-Fi เดียวกับคอมพิวเตอร์ เปิด `http://<IP ของคอมพิวเตอร์>:3000` ใน Safari และอนุญาต Windows Firewall เฉพาะเครือข่ายส่วนตัวเมื่อจำเป็น นี่คือวิธีทดลองในเครือข่ายท้องถิ่น ไม่ใช่ระบบออนไลน์สำหรับร้านจริง เซิร์ฟเวอร์รับการเชื่อมต่อทุก interface จึงควรใช้เฉพาะเครือข่ายที่ไว้ใจ ห้ามเปิดพอร์ตออกอินเทอร์เน็ตโดยตรง

ข้อมูลใน iPad กับคอมพิวเตอร์ **ไม่ใช่ชุดเดียวกัน** ข้อมูลแยกตาม browser profile และ origin (host/port) ของแต่ละเครื่อง การล้างข้อมูลเบราว์เซอร์ทำให้ข้อมูลหาย

## ทำอะไรได้ในรอบแรก

- Dashboard 12 จุด ราคา 20 บาท / 25 นาที ต่อครั้งละ 5 นาที / 5 บาท
- สีเหลืองเมื่อเหลือไม่เกิน 5 นาที สีแดงเมื่อหมด พร้อมข้อความแจ้งเตือนในหน้าเว็บ ไม่มีเสียงหรือ push notification
- หมดเวลาแล้วไม่ปิดคิวเอง พนักงานต้องกดยืนยันจบคิวและปิดไฟด้วยมือ ค่าบริการจึงเข้าในตะกร้า
- เก็บ `endsAt` แบบ epoch milliseconds ใน localStorage ไม่ใช้การลดตัวนับเป็นแหล่งข้อมูล รีเฟรช/กลับจากพักหน้าจอจึงคำนวณใหม่จากเวลาสิ้นสุดเดิม
- ต่อเวลาจากกำหนดสิ้นสุดเดิม แม้กดหลังหมดเวลา เช่น สายไป 6 นาทีแล้วต่อ 5 นาที จะยังหมดเวลา ต้องต่ออีกครั้งตามจริง ไม่มีค่าปรับหรือคิดเงินล่วงเวลาอัตโนมัติ
- เพิ่มสินค้า ชื่อ บาร์โค้ด ราคาทุน ราคาขาย สต๊อกทดสอบ ค้นหาและใส่ตะกร้า นำสินค้าทั้งรายการออกได้
- รวมสินค้าและค่าบริการในบิลทดสอบเดียว ยืนยันแล้วปรับเฉพาะสต๊อกจำลอง และแสดงบิลล่าสุด ไม่รับเงินจริง
- บิลทั้งหมดเก็บใน localStorage แต่ยังไม่มีหน้าประวัติ รายงาน คืนเงิน หรือยกเลิกค่าบริการ ให้ล้างข้อมูลเพื่อเริ่มทดสอบใหม่

ข้อมูลตัวอย่างสร้างโดย `createDemo()` ใน `src/domain.js` แยกด้วย key `neeb20:demo:v1` และทุกบิลมี `demo: true` ไม่มีเส้นทางเชื่อมข้อมูลขายจริง ปุ่มล้างข้อมูลทดสอบจะล้างคิว สินค้า ตะกร้า และบิลของชุดนี้ทั้งหมด

## วิธีทดสอบ

```powershell
npm test
```

ใช้ Node test runner ทดสอบ 3 กรณี: 12 จุดและการคืนค่ากำหนดเวลาหลัง serialize, ช่วงเตือน/หมดเวลาและต่อเวลา/จบคิว, บิลรวมและสต๊อก รวมถึงปฏิเสธสต๊อกไม่พอโดยไม่ตัดบางส่วน (กรณีบิลรวมอยู่ใน test เดียวกัน)

ทดสอบด้วยมือเพิ่มเติม:

1. กดเริ่มจุด 01 ตรวจราคา 20 บาทและเวลา 25 นาที รีเฟรช ตรวจว่ากำหนดสิ้นสุดยังเดิม
2. กด +5 นาที ตรวจเพิ่ม 5 นาทีและราคาเป็น 25 บาท
3. รอให้เหลือ 5 นาทีและหมดเวลา ตรวจสี/ข้อความ และคิวยังค้างจนยืนยันจบ
4. หากต้องการเร่งทดสอบ ใช้ DevTools Console เฉพาะข้อมูลทดสอบดังนี้ แล้วรีเฟรช:

   ```js
   const key = 'neeb20:demo:v1';
   const data = JSON.parse(localStorage.getItem(key));
   if (data.stations[0].session) {
     data.stations[0].session.endsAt = Date.now() + 10000;
     localStorage.setItem(key, JSON.stringify(data));
     location.reload();
   }
   ```

5. ยืนยันจบคิว ตรวจค่าบริการเข้าในตะกร้า เพิ่มหวีทดสอบ 2 ชิ้น บิลกรณีต่อเวลา 1 ครั้งควรเป็น 25 + 29×2 = 83 บาท
6. ยืนยันบิลทดสอบ ตรวจสต๊อกหวีลดจาก 20 เป็น 18 ตะกร้าว่าง และบิลมีป้ายทดสอบ รีเฟรชแล้วบิลยังอยู่
7. เพิ่มสินค้าใหม่พร้อมทุน/ขาย/สต๊อก ลองบาร์โค้ดซ้ำและสั่งเกินสต๊อก ต้องถูกปฏิเสธ
8. ตรวจ layout บน iPad แนวตั้ง/แนวนอนและมือถือ ปุ่มไม่เล็กกว่า 48px การใช้งาน Safari/อุปกรณ์จริงยังต้องตรวจแยก

ข้อจำกัด: ใช้นาฬิกาเครื่อง หากผู้ใช้เปลี่ยนเวลา ตัวนับจะเปลี่ยนตาม การแจ้งเตือนเกิดขณะหน้าเว็บทำงานเท่านั้น iPad อาจพัก tab ได้ ไม่มีการรับประกันแจ้งเตือนตอนล็อกหน้าจอ รุ่นนี้ให้ใช้ **หนึ่งแท็บ หนึ่งเครื่องต่อชุดข้อมูล** event ข้ามแท็บช่วยโหลดข้อมูลใหม่เท่านั้น ไม่ใช่กลไกล็อก การเขียนพร้อมกันอาจทับกัน

## โครงสร้าง

- `index.html` — โครงหน้าและฟอร์มภาษาไทย
- `src/style.css` — layout responsive และสถานะสี
- `src/app.js` — จัดการหน้าจอและ localStorage
- `src/domain.js` — กฎคิว ค่าบริการ บิล สต๊อก และชุดตัวอย่าง
- `server.js` — HTTP static server ใช้ Node built-in เสิร์ฟเฉพาะไฟล์ที่อนุญาต
- `test/domain.test.js` — ทดสอบกฎหลักโดยไม่ต้องมี browser
- `docs/architecture.md` — เทคโนโลยี ฐานข้อมูล และแผนแยกโมดูล

Repository เริ่มต้นมีเพียง README ไม่มีแอปหรือระบบฐานข้อมูลเดิม รอบนี้เลือก JavaScript ES modules + Node built-in เพื่อลดต้นทุนและเปิดบน Windows ได้ง่าย ไม่ต้องมี build step ไม่ต้องใช้รหัสผ่านหรือ API key สำหรับต้นแบบ

## งานถัดไป

เลือก backend ตาม `docs/architecture.md` ก่อนใช้หลายเครื่อง เพิ่มบัญชี/สิทธิ์พนักงาน, ธุรกรรมและ audit log, ประวัติบิล/คืนเงิน, เงินสด/การชำระเงินจริง, จองสระ100 ออนไลน์, ช่าง/ค่าคอมมิชชัน, รายงานและสำรองข้อมูล ทดสอบการทำงานบน Safari จริงและพฤติกรรมพักหน้าจอ ระบบนี้ยังไม่ผ่านการทดสอบกับเครื่องพิมพ์ ลิ้นชักเงิน หรือเครื่องสแกนจริง

## เปิด Preview บนคอมพิวเตอร์

1. ต้องมีไฟล์ต้นแบบรอบนี้อยู่ในคอมพิวเตอร์ก่อน หากใช้ Codex Cloud ให้ดาวน์โหลด/นำการเปลี่ยนแปลงจาก task ไปไว้ในโฟลเดอร์โครงการบน Windows (การแก้ไฟล์ใน Cloud ยังไม่หมายความว่า push เข้า GitHub แล้ว)
2. เปิดโฟลเดอร์ใน VS Code แล้วเลือก Terminal → New Terminal หรือเปิด PowerShell ในโฟลเดอร์ที่มี `package.json`
3. รัน `node --version` ให้เป็น 22 ขึ้นไป แล้วรัน `npm start` เปิด Terminal ค้างไว้ ไม่ต้อง `npm install` สำหรับตัวแอป
4. เปิด Chrome หรือ Edge พิมพ์ `http://localhost:3000` ในแถบที่อยู่ จะเห็น Station 12 จุด เลื่อนลงด้านล่างเพื่อดู POS
5. ปุ่ม “ล้างข้อมูลทดสอบ” ใช้เริ่มใหม่ได้ ไม่มีข้อมูลลูกค้าจริงในชุดตัวอย่าง

เซิร์ฟเวอร์ที่รันใน Codex Cloud กับ Windows เป็นคนละเครื่อง ที่อยู่ localhost บน Windows จะเข้าได้เมื่อรัน `npm start` บน Windows แล้วเท่านั้น ในหน้าตั้งค่า Cloud onboarding นี้ไม่มี public Preview URL ที่เผยแพร่ให้เปิดจากคอมพิวเตอร์ได้อัตโนมัติ ภาพหน้าจอที่บันทึกระหว่างทดสอบเป็นภาพนิ่ง ไม่ใช่เว็บโต้ตอบ

## ผลตรวจสอบรอบ Preview

- Node tests 3 ชุดผ่าน และ HTTP หน้าเว็บ/ไฟล์ JavaScript/CSS ตอบกลับสำเร็จ
- ทดสอบ UI ด้วย Chromium จริงแบบ headless: 12 จุด, เริ่มคิว, รีเฟรชแล้วกำหนดสิ้นสุดเดิม, ต่อเวลา, เตือนใกล้หมด, หมดเวลาและยืนยันจบ
- บิลบริการ 25 บาท + หวี 2 ชิ้น 58 บาท รวม 83 บาทถูกต้อง สต๊อกทดสอบเหลือ 18 และบิลยังอยู่หลังรีเฟรช
- เพิ่มสินค้า ค้นหา ตรวจสต๊อกไม่พอ และนำสินค้าออกผ่าน
- พบและแก้การค้นหาบาร์โค้ดอังกฤษตัวใหญ่ เช่น TEST001 แล้วทดสอบ UI ซ้ำผ่าน
- ตรวจ viewport คอมพิวเตอร์ 1440px, แท็บเล็ต 768px และมือถือ 390px ไม่มีการล้นแนวนอน และไม่พบ JavaScript page error ในเส้นทางที่ทดสอบ
- นี่คือการจำลอง viewport บน Chromium ยังไม่ใช่ผลทดสอบ Safari หรือ iPad จริง

## ทางเลือกไฟล์เดียวสำหรับ Windows (ไม่ต้องติดตั้ง Node.js)

ไฟล์ `NEEB20-DEMO.html` รวมหน้าเว็บ CSS และ JavaScript ไว้ด้วยกัน ใช้เฉพาะข้อมูลทดสอบ เมื่อนำไฟล์ไปไว้บน Windows ให้คลิกขวา → Open with → Google Chrome หรือ Microsoft Edge แล้วทดลอง Station และ POS ได้ ไม่ต้องเปิด Terminal หรือเชื่อมเซิร์ฟเวอร์

ข้อจำกัด: การบันทึก localStorage เมื่อเปิดผ่าน `file://` ขึ้นกับเบราว์เซอร์/นโยบายองค์กร ย้ายหรือเปลี่ยนชื่อไฟล์อาจทำให้ไม่พบข้อมูลเดิม หากเบราว์เซอร์บล็อกไฟล์หรือบันทึกไม่ได้ ให้ใช้วิธี Node.js (`npm start`) แทน อย่าปิดข้อกำหนดความปลอดภัยของเบราว์เซอร์ ข้อมูลตัวอย่างไม่มีข้อมูลลูกค้าจริงและไม่ได้ซิงก์กับระบบจริง

สร้างไฟล์นี้ใหม่หลังแก้ต้นฉบับด้วย `node scripts/build-demo.js` อย่าแก้ไฟล์ generated โดยตรง ตัวไฟล์รวมผ่านการทดสอบ UI บน Chromium ผ่าน HTTP แล้ว แต่การเปิด `file://` ใน Cloud นี้ถูกนโยบายเบราว์เซอร์บล็อก จึงยังยืนยันการดับเบิลคลิกบน Windows จริงไม่ได้

Cloud เซสชันปัจจุบันมีเซิร์ฟเวอร์ภายใน แต่ไม่มีเครื่องมือเผยแพร่พอร์ต/สร้าง public Live Preview URL ให้ผู้ใช้ การเปิด localhost ของคอมพิวเตอร์จะไม่เข้าถึง Cloud และไฟล์ที่สร้างยังไม่ได้ push ไป GitHub ต้องนำไฟล์จาก task ไปไว้บนคอมพิวเตอร์ก่อน
