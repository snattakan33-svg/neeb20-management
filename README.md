# หนีบ20 — Prepaid Management Demo

ระบบทดลองภาษาไทย: Station 12 จุด ชำระก่อนเริ่ม 20 บาท/25 นาที ต่อเวลาแบบชำระก่อน 5 บาท/5 นาที พร้อม POS สต๊อก และรายงาน **ทุกข้อมูลเป็นข้อมูลทดสอบ ไม่ใช่ยอดขายจริง ไม่เชื่อมธนาคาร ไม่ตรวจ QR อัตโนมัติ ไม่เชื่อมไฟฟ้า**

## เปิดบน Windows ทีละขั้น

1. ลงชื่อเข้า GitHub แล้ว [ดาวน์โหลด ZIP สาขา neeb20/prototype-demo](https://github.com/snattakan33-svg/neeb20-management/archive/refs/heads/neeb20/prototype-demo.zip)
2. คลิกขวา ZIP → **Extract All / แยกทั้งหมด** แล้วเข้าโฟลเดอร์ที่แตกออกมา ต้องเห็น `START-NEEB20.cmd` และ `package.json` อย่าเปิดจากข้างใน ZIP
3. ติดตั้ง **Node.js 24 LTS** จาก https://nodejs.org เพียงครั้งเดียว (ขั้นต่ำ 22.13)
4. ดับเบิลคลิก **START-NEEB20.cmd** เปิดหน้าต่างนี้ค้างไว้ รอเซิร์ฟเวอร์เริ่มแล้วจะสั่งเปิดเบราว์เซอร์ให้อัตโนมัติ ถ้าไม่เปิด ให้เข้า `http://127.0.0.1:3000` ด้วย Edge/Chrome
5. เห็น **SERVER DEMO** ด้านบนแล้วจึงทดลอง เริ่มต้นเป็นพนักงานทดสอบ เปลี่ยนเป็นผู้จัดการทดสอบได้ในช่องผู้ดำเนินการ
6. ปิดระบบด้วย Ctrl+C ในหน้าต่างเซิร์ฟเวอร์ ข้อมูลยังอยู่ใน `.data/demo.sqlite` ไม่ต้องลงแพ็กเกจใด ๆ เพื่อเปิดแอป

หากไม่เปิด: อย่าปิดหน้าต่างข้อความผิดพลาด ถ่ายภาพข้อความส่งให้ตรวจได้ ถ้าแจ้งไม่พบ Node ให้ติดตั้งข้อ 3 ถ้าพอร์ตใช้งานอยู่ ให้ปิดเซิร์ฟเวอร์เก่าก่อน ไม่ต้องแก้ firewall เพื่อเปิดบนเครื่องเดียว

วิธีผ่าน PowerShell แทนดับเบิลคลิก:

```powershell
node --version
npm start
```

จากนั้นเปิด `http://127.0.0.1:3000` หากพอร์ตชนและต้องการเปลี่ยน ใช้ `$env:PORT=3001` แล้ว `npm start` และเปิดพอร์ต 3001

**Cloud กับ Windows เป็นคนละเครื่อง** localhost บน Windows ไม่ได้เชื่อม Cloud เซสชัน Cloud นี้ไม่มี public Live Preview URL อัตโนมัติ ต้องดาวน์โหลดและเปิดบนเครื่องตามขั้นตอนข้างต้น

### อัปเดตจากรุ่นเดิมโดยรักษาข้อมูล

- กด **สำรองข้อมูลทดสอบ** ในรุ่นเดิมก่อน แล้วปิดเซิร์ฟเวอร์เดิมให้เรียบร้อย
- แตก ZIP ใหม่คนละโฟลเดอร์ เก็บโฟลเดอร์เดิมไว้ อย่าลบฐานข้อมูลเพื่อแก้ปัญหา
- หากต้องการใช้ฐาน Server Demo เดิม ให้คัดลอกโฟลเดอร์ `.data` ทั้งโฟลเดอร์จากรุ่นเดิมไปโฟลเดอร์ใหม่ **หลังปิดเซิร์ฟเวอร์แล้วเท่านั้น** อย่าคัดลอกไฟล์ SQLite เดี่ยวขณะระบบทำงาน และอย่าเปิดฐานสำเนาสองชุดเป็นระบบหลักพร้อมกัน
- รุ่นนี้อัปเกรด schema v2 → v3 ใน SQLite transaction พร้อมเก็บ snapshot เดิมใน `schemaArchives` ไม่ลบธุรกรรม/บิล/audit เดิม และไม่สร้างรายรับย้อนหลัง
- Session เดิมที่ยังค้างเป็น `legacyPostpaid` กำหนดเวลาคงเดิม มีปุ่มรับยอดค้างรุ่นเก่า ส่วน Session ใหม่ใช้ Prepaid เท่านั้น ธุรกรรมเก่าที่ไม่ทราบหมวด/ช่องทางแสดง `legacy/unknown` ไม่เดาว่าเป็นเงินสดหรือ QR
- ฐานข้อมูล Server Demo แยกจากข้อมูล Local Demo ไม่โอนข้อมูลในเบราว์เซอร์เข้าเซิร์ฟเวอร์ให้อัตโนมัติ ยังไม่มีหน้า import/restore JSON

## ขั้นตอนทดลองหน้าร้าน

### Station และ Prepaid

- เลือกจุดว่าง 01–12 หน้าต่างแสดง 20 บาท/25 นาที เลือก **เงินสด/QR** และติ๊กยืนยันตรวจรับเงิน พนักงานต้องตรวจเอง ใน Demo ช่องนี้เป็นการจำลอง ไม่มีการหักเงินจริง
- เมื่อบันทึกสำเร็จ: สร้าง Session และ Transaction ID เฉพาะ รับเงิน 20 บาทครั้งเดียวและเริ่มจับเวลาในธุรกรรมเดียว ถ้าบันทึกล้มเหลวจะไม่เริ่มคิว และจุดที่มีคิวเริ่มซ้ำไม่ได้
- **ก่อนยืนยันรับชำระ** กดยกเลิกหน้าต่างได้ ไม่มี Session ไม่มีรายการเงินหรือค่าบริการค้าง
- **ยืนยันเริ่มใช้จริง** เมื่อเริ่มใช้งาน บันทึกเวลาใช้จริงแยกจากเวลาเริ่มจับเวลาหลังรับชำระ เพื่อใช้พิจารณายกเลิกก่อนใช้และรายงานระยะใช้งาน หากยังไม่กด ระบบรายงานว่าไม่ทราบ/ยังไม่ยืนยัน ไม่เดาระยะใช้จริง
- **+5 นาที / 5 บาท** ต้องเลือกช่องทางและยืนยันรับเงินอีกครั้ง เพิ่มเวลา Session เดิมจากกำหนดสิ้นสุดเดิม พร้อม payment ประเภท `extension` ใช้บิลเดิม ไม่สร้างคิวใหม่
- **ย้ายจุด / แก้ไขจุดที่เริ่มผิด** ต้องระบุเหตุผล เป้าหมายต้องว่าง ย้าย Session/บิล/กำหนดสิ้นสุดเดิม ไม่รับเงินใหม่ ตรวจสถานะล่าสุดซ้ำใน transaction
- **จบคิว** ตรวจหมายเลขจุด Session เวลา และยอดก่อนยืนยัน ปลดจุดเท่านั้น **ไม่เพิ่มรายรับ ไม่รับเงินซ้ำ** หมดเวลาจะแสดงสีแดงและค้างจนพนักงานปิดเอง
- **กู้คืนคิว** ให้ผู้จัดการระบุเหตุผลและจุดว่าง กู้ Session/บิลเดิม ไม่รับเงินใหม่ ไม่รีเซ็ตเวลา ถ้าเวลาหมดก็ยังแสดงหมดเวลา

### ยกเลิกและคืนเงิน

1. พนักงานส่งคำขอยกเลิกพร้อมเหตุผล
2. ผู้จัดการเปิดรายการคิวแล้วอนุมัติ:
   - ยังไม่ได้ใช้จริง: ต้องคืนเต็มยอดที่รับสุทธิ ยืนยันช่องทาง/คืนเงินแล้ว ระบบบันทึกยกเลิกและ refund พร้อมกัน ทำให้ยอดสุทธิของบิลเป็น 0
   - ใช้แล้ว: ผู้จัดการกำหนดยอดคืนตามนโยบายร้านได้ตั้งแต่ 0 ถึงยอดรับสุทธิ พร้อมเหตุผล หากมีประวัติยืนยันเริ่มใช้จริงจะเลือกอ้างว่ายังไม่ใช้ไม่ได้
3. ยังมีปุ่มคืนเงินบริการแยกสำหรับผู้จัดการตามนโยบาย แต่ไม่เกินยอดรับสุทธิ ไม่เปิดหนี้เดิมให้เก็บซ้ำอัตโนมัติ

การรับเงินและคืนเงินเดิมไม่ถูกลบ รายการคืนมีรหัสเฉพาะและอ้างอิง Transaction รับเงินเดิม ปุ่มถูกล็อกระหว่างบันทึก คำสั่งเดิม retry ได้แต่ไม่สร้างรายการซ้ำ การยกเลิกที่อนุมัติไปแล้วไม่คืนซ้ำแม้ส่งคำสั่งใหม่

### POS และสต๊อก

- ผู้จัดการเพิ่ม/แก้ไขสินค้า: SKU ชื่อ หมวด บาร์โค้ด ทุน ราคาขาย สต๊อกตั้งต้น และเปิด/ปิดขาย ไม่ลบสินค้า/ประวัติเดิม
- พนักงานค้นหาชื่อ SKU หมวดหรือบาร์โค้ด ใส่ตะกร้า นำออกได้ ตะกร้าเป็นชุดกลางหนึ่งชุดใน Server Demo นี้
- เลือกเงินสด/QR และยืนยันรับเงินก่อนขาย จึงบันทึกธุรกรรมหมวด `product` พร้อมบิลและตัดสต๊อกใน transaction เดียว ป้องกันขายเกินสต๊อก สินค้าปิดขายขายไม่ได้ และถ้าราคาเปลี่ยนหลังใส่ตะกร้าต้องนำออกแล้วเพิ่มใหม่
- **รับเข้า** ระบุจำนวนบวกและเหตุผล พนักงานทำได้ / **ปรับสต๊อก** ใช้จำนวนเพิ่มหรือลดพร้อมเหตุผล ผู้จัดการเท่านั้น สต๊อกติดลบไม่ได้
- **คืนสินค้า**: ผู้จัดการเปิดรายการขายสินค้า เลือกจำนวนไม่เกินที่ขายลบคืนแล้ว ระบุเหตุผล ช่องทางคืนและยืนยัน เลือกว่าจะรับสินค้าคืนเข้าสต๊อกหรือไม่ คืนตามราคาขณะขาย ไม่ใช้ราคาปัจจุบัน
- เก็บ stock movements ทุกครั้ง พร้อมก่อน/หลัง ผู้ทำ เวลา และ Transaction อ้างอิงเมื่อเกี่ยวกับขาย/คืน แสดงล่าสุด 50 รายการ สำรองข้อมูลเพื่อดูทั้งหมด

## รายงาน

เลือก **รายวัน / รายเดือน / ช่วงวันที่** ตาม **Asia/Bangkok** รวมถึงวันที่สุดท้าย:

- รายรับค่าบริการ 20 บาท, ต่อเวลา, สินค้า และข้อมูลเก่าไม่ทราบหมวด แยกกัน
- รับเงินรวม รายการคืนเงิน และสุทธิ พร้อมเงินสด/QR แยกยอดรับ คืน และสุทธิ ธุรกรรมเก่าไม่ทราบช่องทางแยก `unknown`
- รายรับนับจาก payment ที่ยืนยันสำเร็จ หัก refund ตามวันที่คืนจริง ไม่ใช่จำนวนเริ่ม/จบคิว เช่นรับเมื่อวานคืนวันนี้ รายงานวันนี้แสดงรายการคืนและสุทธิติดลบได้
- Session ที่ **เริ่มในช่วงวันที่เลือก**: จำนวนคิว สถานะ เวลาเริ่มจับเวลา กำหนดสิ้นสุด เวลาจบ/ยกเลิก จุดที่เคยใช้ จำนวนย้าย และเวลาใช้งานจริงจากช่วงยืนยันเริ่มใช้จนจบ/ยกเลิก ไม่รวมช่วงพักระหว่างจบผิดกับกู้คืน
- แสดงจำนวนเหตุการณ์จบ/ยกเลิกในช่วงวันที่แยกด้วย เพราะบางคิวอาจเริ่มก่อนช่วงวันที่
- ประวัติธุรกรรม รหัสอ้างอิง Session/บิล/รายการเดิม พนักงาน เวลา เหตุผล และส่งออก CSV สำหรับ Excel (มีป้ายข้อมูลทดสอบ)

รายงานเป็น **รายรับจากธุรกรรมทดสอบ** ไม่ใช่กำไรหรือเอกสารภาษี ไม่มีการอ่านยอดธนาคาร ไม่มี QR จริงหรือ payment gateway

## การบันทึกและสิทธิ์ — ข้อจำกัดสำคัญ

Server Demo เก็บข้อมูลถาวรใน `.data/demo.sqlite` ใช้ SQLite `BEGIN IMMEDIATE` ตรวจ revision/จุดว่าง/stock/คำสั่งซ้ำ แล้ว commit เงิน เวลาและประวัติพร้อมกัน หากผิดพลาด rollback ทั้งคำสั่ง เก็บ Audit และ Idempotency keys ไม่หมดอายุในรุ่นนี้ ไม่พึ่ง Local Storage เป็นฐานรายได้/สต๊อกของ Server Demo

คำสั่งที่ผลเครือข่ายไม่แน่นอนจะเก็บรหัสคำสั่งค้างใน sessionStorage เพื่อ retry คำสั่งเดิม หลังรีเฟรชจะตรวจว่าบันทึกแล้วหรือยัง จึงไม่สร้างคำสั่งรับเงินใหม่โดยไม่ตรวจสอบ sessionStorage นี้เก็บคำสั่งค้างเท่านั้น ไม่ใช่ฐานข้อมูลรายได้

**การเลือก staff/manager ยังเป็นการจำลอง ไม่มี authentication จริง** ใครเข้า Demo ได้ก็เลือกผู้จัดการได้ แม้ command handler จะตรวจบทบาท ก่อน production ต้องเพิ่ม login, server-side identity/approval, สิทธิ์ฐานข้อมูล, HTTPS, backup/restore ที่ทดสอบแล้ว และ schema normalized ห้ามใช้ข้อมูลลูกค้าหรือรับเงินจริงกับรุ่นนี้ ไม่มีรหัสผ่าน/ข้อมูลลับฝังในโค้ด

Server ใช้เวลาบันทึกของเซิร์ฟเวอร์ หน้าเว็บปรับ offset จาก server timestamp สำหรับ countdown แต่ต้องทดสอบ clock drift/latency บนอุปกรณ์จริงเพิ่มเติม หน้าเว็บพัก/ล็อกจอไม่รับประกันแจ้งเตือน พนักงานเปิด–ปิดไฟด้วยมือทั้งหมด

## ทดลองหลายอุปกรณ์

ค่าเริ่มต้นผูก `127.0.0.1` เพื่อเครื่องเดียว หากทดสอบ LAN ที่ไว้ใจ เปิด PowerShell:

```powershell
$env:HOST="0.0.0.0"
npm start
```

เปิด `http://<IP ของเครื่องเซิร์ฟเวอร์>:3000` บนแต่ละเครื่อง/iPad ใน Wi-Fi เดียวกัน ต้องใช้ **เซิร์ฟเวอร์ตัวเดียว** อนุญาต firewall เฉพาะ private network เมื่อจำเป็น ห้ามเปิดพอร์ตออกอินเทอร์เน็ต คำสั่งชนกัน/ข้อมูลเก่าตอบ conflict ให้ปิดหน้าต่างแล้วตรวจสอบใหม่ ไม่ปรับ revision แล้ว retry โดยไม่ให้พนักงานตรวจ

## Local Demo ไฟล์เดียว

`NEEB20-DEMO.html` ยังอยู่สำหรับทดลอง UI แบบไม่ติดตั้ง Node เท่านั้น มีป้าย **LOCAL DEMO** ไม่ใช่ระบบรายได้/สต๊อกกลาง ต้องใช้ Server Demo เพื่อทดสอบข้อมูลถาวรและหลายอุปกรณ์ Browser/นโยบายองค์กรอาจบล็อก file:// หรือ storage จึงไม่รับประกันเปิดไฟล์ได้ทุกเครื่อง อย่าปิดระบบความปลอดภัยเพื่อเปิด

Local Demo ใช้ key `neeb20:demo:v3` นำเข้าจาก v2/v1 ใน origin เดียวกัน เก็บข้อมูลเดิมไว้ ไม่ลบ key เก่า ไม่เดาช่องทางรับเงินเก่า ไม่โอนข้อมูลข้ามเครื่องหรือ path ให้อัตโนมัติ

```powershell
npm install --no-save --package-lock=false --ignore-scripts playwright
npx playwright install chromium
npm run test:browser
```

ใช้ฐาน SQLite ในหน่วยความจำแยกจากข้อมูลร้าน ทดสอบ Chromium รวมการยกเลิกก่อนจ่าย, prepaid 20, ต่อเวลา QR 5, ย้ายจุดและ refresh, จบไม่เพิ่มเงิน, POS 58, กู้คืน, คืนเต็มก่อนใช้, สอง browser contexts, สินค้า/สต๊อก/คืนสินค้า, รายงาน/API/CSV และ retry หลัง refresh กำหนด `NEEB20_CHROMIUM` หรือ `NEEB20_PLAYWRIGHT_MODULE` ได้ถ้าใช้เครื่องมือที่ติดตั้งอยู่อีกตำแหน่ง

ทดสอบด้วยมือ: เริ่มจุด 01 เงินสด 20 → ต่อ QR 5 → ย้าย 03 → จบคิว รายรับบริการยัง 25; ขายหวี 2 ชิ้น QR 58 → สุทธิ 83; เปิดคิวอีกจุด 20 โดยยังไม่กดเริ่มใช้จริง → ขอและอนุมัติคืนเต็ม 20 → สุทธิกลับ 83; คืนหวีหนึ่งชิ้น 29 → สุทธิ 54 และ stock เพิ่มคืนหนึ่งชิ้น ตรวจข้อมูลหลังปิด/เปิด server ใหม่

ยังต้องทดสอบบน Windows, Safari/iPad และเครื่องพิมพ์/อุปกรณ์จริง การจำลอง viewport ไม่ใช่การทดสอบอุปกรณ์จริง

## ไฟล์หลัก

- `src/domain.js` — Prepaid commands, Session, บิล, payment/refund, SKU/stock/return, audit, สิทธิ์ และ migration
- `src/reports.js` — ช่วงวันที่ไทย รายรับ/คืน แยกหมวด/ช่องทาง การใช้งานและ CSV
- `src/app.js`, `index.html`, `src/style.css` — Station/POS เดิม พร้อมหน้ารับชำระ จัดการสินค้าและรายงาน
- `server.js`, `server/store.js` — API, server timestamp, reports และ SQLite transaction/upgrade
- `test/domain.test.js`, `test/server.test.js`, `test/reports.test.js` — ทดสอบกฎ/API/persistence/report
- `scripts/browser-test.mjs` — Chromium integration
- `START-NEEB20.cmd`, `scripts/start-demo.js` — เปิด server บน Windows และสั่งเปิด browser เมื่อพร้อม
- `scripts/build-demo.js`, `NEEB20-DEMO.html` — Local Demo รวมไฟล์เดียว
