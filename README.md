## เปิดบน Windows

1. ลงชื่อเข้า GitHub แล้ว [ดาวน์โหลด ZIP สาขา neeb20/prototype-demo](https://github.com/snattakan33-svg/neeb20-management/archive/refs/heads/neeb20/prototype-demo.zip)
2. คลิกขวา ZIP → **Extract All / แยกทั้งหมด** แล้วเข้าโฟลเดอร์ที่มี `START-NEEB20.cmd` และ `package.json` อย่าเปิดจากภายใน ZIP
3. ติดตั้ง **Node.js 24 LTS** จาก https://nodejs.org เพียงครั้งเดียว (ขั้นต่ำ 22.13)
4. ดับเบิลคลิก **START-NEEB20.cmd** เปิดหน้าต่างนี้ค้างไว้ ระบบจะสั่งเปิด browser หลังเซิร์ฟเวอร์พร้อม หากไม่เปิด ให้พิมพ์ `http://127.0.0.1:3000` ใน Edge หรือ Chrome
5. ต้องเห็น **SERVER DEMO** ด้านบนก่อนทดลอง ข้อมูลอยู่ถาวรใน `.data/demo.sqlite` ปิดเซิร์ฟเวอร์ด้วย Ctrl+C ไม่ลบฐานข้อมูล

ถ้าเปิดไม่ได้ ให้ถ่ายภาพข้อความในหน้าต่างเซิร์ฟเวอร์ ถ้าแจ้งไม่พบ Node ให้ทำข้อ 3 ถ้าพอร์ตใช้งานอยู่ให้ปิดเซิร์ฟเวอร์รุ่นเก่าก่อน รุ่นใหม่จะไม่อัปเกรดฐานของรุ่นเก่าถ้าพอร์ตยังถูกใช้

ทางเลือก PowerShell ในโฟลเดอร์โครงการ:

```powershell
npm start
```

ไม่ต้อง `npm install` เพื่อเปิดแอปหรือ Node tests หากต้องการพอร์ตอื่น ใช้ `$env:PORT=3001` แล้ว `npm start` จากนั้นเปิดพอร์ต 3001

**Cloud กับ Windows เป็นคนละเครื่อง** localhost บน Windows ไม่เข้าถึงเซิร์ฟเวอร์ใน Cloud และเซสชันนี้ไม่มี public Live Preview URL อัตโนมัติ ต้องดาวน์โหลดโค้ดและรันบนคอมพิวเตอร์ก่อน

## จัดการสินค้า / SKU / สต๊อกผ่านเว็บ (v0.7.0)

เลือกผู้จัดการทดสอบ → เมนู **สินค้า / SKU / สต๊อก** → **เพิ่ม SKU ใหม่** จัดการชื่อ รูปภาพ หน่วยนับ หมวด ราคาทุน/ขาย ขั้นต่ำ เปิดปิดขาย ค้นหาและกรองสถานะได้ ไม่ต้องแก้โค้ด รูปเลือกไฟล์ PNG/JPEG/WebP ต้นฉบับไม่เกิน 12 MB (ย่อให้อัตโนมัติ) หรือใช้ HTTPS

รับเข้าแยกล็อตและต้นทุนได้ ปรับเพิ่ม/ลดโดยมีประวัติ พนักงานส่งผลตรวจนับแล้วผู้จัดการอนุมัติ หากสต๊อกเคลื่อนไหวระหว่างรอจะบล็อกให้ตรวจใหม่ รหัสเดิมหลังเปลี่ยน SKU สงวนไว้และค้นหาได้ ไม่เปลี่ยนธุรกรรมย้อนหลัง ไม่เปิดให้ลบสินค้าถาวร

รายงานต่อ SKU/ขายดี/ขายช้า/ต่ำ/หมด/มูลค่าปัจจุบัน พร้อม CSV ใช้ช่วงวันที่จากสรุปรายได้ **กำไรยังใช้ทุนมาตรฐาน ณ ตอนขายตามระบบเดิม** ต้นทุนรับเข้าล็อตและมูลค่าตามล็อตแสดงแยก ไม่เปลี่ยนต้นทุนขายเป็น FIFO โดยอัตโนมัติ อ่านสูตร ตัวอย่าง และขั้นตอนทดสอบใน [คู่มือ SKU และสต๊อก](docs/sku-inventory.md)

## เมนูใหม่: สรุปรายได้ / กระทบยอด / ปิดกะ

กดเมนูด้านบน เลือกวัน/สัปดาห์ ISO/เดือน/ช่วงวันที่ หรือย้อนหลังทั้งหมด และกรองผู้ทำรายการเงินได้ มีกราฟสุทธิตามวัน/สัปดาห์/เดือน กดแต่ละบิลดูรายละเอียดได้ ส่งออกสรุป/รายพนักงาน ธุรกรรม บิล และกะเป็น CSV และพิมพ์รายงาน

- Dashboard รวมเฉพาะ payment ที่สำเร็จ หัก refund ตามวันคืน แยกบริการ ต่อเวลา สินค้า เงินสด/QR บิลรับเงิน Session และบิลค้างปัจจุบันซึ่งไม่ใช่รายได้ สระ100 แสดงเมื่อมีธุรกรรมที่รองรับ แต่ยังไม่มีโมดูลขาย/จองสระ100 จึงไม่สร้างยอดตัวอย่างปลอมขึ้นมา
- เปิดกะด้วยผู้รับผิดชอบและเงินทอนตั้งต้น เป็นลิ้นชักกลางหนึ่งกะเปิดต่อเวลา รองรับหลายกะต่อวันแบบต่อเนื่อง ไม่รองรับหลายลิ้นชักพร้อมกัน
- หลังเปิดใช้กะครั้งแรก รายการรับ/คืนเงินใหม่ต้องอยู่ในกะเปิด ข้อมูลเก่าไม่ถูกจับเข้ากะใหม่โดยเดา แสดงรายการยังไม่ผูกกะให้ผู้จัดการสร้างกะย้อนหลังตามหลักฐานได้ ห้ามช่วงซ้อน/รายการซ้ำ
- ส่งยอดนับจริงและหลักฐาน QR → รอผู้จัดการตรวจและอนุมัติ → ล็อกยอดเดิม หากแก้หลังอนุมัติต้องสร้าง correction พร้อมเหตุผล ไม่แก้ payment หรือยอดอนุมัติเดิม
- เงินทอนตั้งต้น/เติมเงิน/นำเงินออก ไม่ใช่ยอดขาย ผลต่างสดและ QR ไม่ถูกกลบกัน แม้สุทธิรวม 0 แต่สดขาดและ QR เกิน ระบบยังขึ้นรอตรวจสอบ

**ลองข้อมูลตัวอย่างง่ายที่สุดบน Windows:** หลังติดตั้ง Node.js ให้ดับเบิลคลิก `OPEN-RECONCILIATION-DEMO.cmd` ระบบจะสร้าง/เปิดฐานทดสอบแยกที่พอร์ต 3001 โดยไม่เปลี่ยน `.data/demo.sqlite` เดิม เลือกย้อนหลังทั้งหมด จะพบกะยอดตรง กะเคยขาด 5 บาทที่มีรายการแก้ไข และกะเปิดให้ทดลองต่อ

## Flow Station และบิลเดิม

### เริ่ม / เพิ่มรายการ

- กด **เริ่มคิว 20฿**: เริ่ม 25 นาทีทันทีตามเวลา server สร้าง Session ID และ Bill ID เฉพาะ พร้อมรายการ `ค่าบริการหนีบ20` 20 บาท บิล **UNPAID** ยังไม่มี payment/รายรับ
- กด **+5 นาที / 5฿**: เพิ่ม 5 นาทีจาก deadline เดิม และ charge 5 บาทในบิลเดิมทันที ไม่รับเงิน ไม่สร้างบิลใหม่ มีป้องกันกดซ้ำระหว่างบันทึก/การกดติดกันอย่างรวดเร็ว และคำสั่งเดิม retry ไม่เพิ่มซ้ำ
- กด **เพิ่มสินค้า**: เลือกจาก catalog POS เดียวกัน กำหนดจำนวน เห็นรายการเดิม/ยอดหลังเพิ่ม เพิ่มหลายรายการหรือหลายชิ้นได้ ราคา/ทุนบันทึก snapshot ตอนเพิ่ม ในหน้าคิดเงินสามารถนำสินค้าที่ยังไม่จ่ายออกได้โดยต้องระบุเหตุผล รายการเดิมถูกทำเครื่องหมาย void พร้อม Audit ไม่ลบประวัติ
- โครง charges รองรับ kind/name/quantity/unit price สำหรับเพิ่มบริการอื่นในอนาคต รอบนี้ยังไม่มีหน้าสร้างบริการใหม่

ตัวอย่าง: 20 + ต่อเวลา 5 + สินค้า 29 + น้ำ 10 = **64 บาท** ทั้งหมดอยู่ Bill/Session เดิม และยังไม่ใช่รายรับจนกว่าจะชำระ

### คิดเงิน / ชำระเงิน

กด **คิดเงิน / ชำระเงิน** จะเห็น Bill ID, Session ID, Station, รายการ ราคา จำนวน และยอดรวม เลือก **เงินสด/QR** แล้วติ๊กยืนยันตรวจรับเงินก่อนยืนยัน (ใน Demo เป็นการจำลอง ไม่อ่านบัญชีธนาคาร)

เมื่อบันทึกสำเร็จ ระบบตรวจ stock แล้วบันทึกพร้อมกันใน SQLite transaction:

- เปลี่ยนสถานะบิลเป็น **PAID** เก็บเวลาชำระ ช่องทาง พนักงาน และ Payment ID
- สร้าง receipt เดียวและ financial ledger lines แยกบริการ/ต่อเวลา/สินค้า โดย ledger ทุกบรรทัดอ้าง Bill/Session และ Payment ID เดียวกัน แต่ละบรรทัดมี Transaction ID เฉพาะ ไม่ได้นับยอดกลุ่มกับยอดย่อยซ้ำ
- ตัดสต๊อกสินค้าและ Audit ใน commit เดียว หากผิดพลาด rollback ทั้งบิล ไม่มีการรับค่าบริการบางส่วนแล้วสินค้าล้มเหลว
- คำสั่งเดิมส่งซ้ำจะคืนผลเดิม ไม่เพิ่มเงินหรือ stock movement ใหม่ คำสั่งใหม่พยายามจ่ายบิลเดิมอีกถูกปฏิเสธ

**หลัง PAID/REFUNDED ล็อกรายการ** ไม่เพิ่มสินค้า/ต่อเวลา/แก้ยอดย้อนหลัง แต่ยังย้ายหรือจบ Station ได้ รุ่นนี้ยังไม่มีขั้นตอนปรับบิลที่รับเงินแล้วเพื่อเรียกเก็บเพิ่ม ใช้สิทธิ์ผู้จัดการคืนเงิน/VOID ตามนโยบาย ไม่สร้างบิลหลักที่สองอัตโนมัติ

### สต๊อก: ตัดตอนจ่าย ไม่จองระหว่างเปิดบิล

รุ่นนี้เลือกวิธี **ตรวจและตัดตอนชำระเงิน** ไม่ใช้ stock reservation การเพิ่มสินค้าหรือยกเลิกบิล UNPAID จึงไม่เปลี่ยน stock และไม่มีจำนวนจองที่ต้องคืน สองบิลอาจเลือกสินค้าชิ้นสุดท้ายพร้อมกันได้ แต่มีเพียงบิลที่ชำระสำเร็จก่อนที่ได้สินค้า บิลที่เหลือถูกปฏิเสธทั้งคำสั่ง ให้พนักงานนำสินค้าหมดออก/จัดหาสินค้าและตรวจใหม่ Station ยังไม่ถูกปล่อยอัตโนมัติ

### ย้าย / จบ / ยกเลิก

- **ย้ายจุด** ต้องระบุเหตุผล เลือกจุดว่าง ย้าย Session+บิลเดิมพร้อมรายการทั้งหมด ไม่เปลี่ยน deadline ไม่เพิ่ม 20 บาท ไม่รับเงินใหม่ ตรวจสถานะล่าสุดซ้ำขณะบันทึก
- **จบคิว** แสดง Station/Session/เวลา/ยอดก่อนยืนยัน ทำหน้าที่ปิดการใช้งานและปล่อยจุดเท่านั้น ไม่มี transaction/รายรับใหม่
- หากบิลยังไม่จ่าย จะแสดง **“บิลนี้ยังไม่ได้ชำระเงิน ต้องการไปหน้าคิดเงินหรือไม่?”** และปุ่มไปคิดเงิน ยกเลิกหน้าต่างนี้จะไม่จบคิว ฝั่ง server ก็บล็อก finish ของ UNPAID แม้เรียก API ตรง ๆ
- หมดเวลาแสดงสีแดงและรอพนักงานปิดจุด ไม่มีการปล่อยว่างเอง รีเฟรชยังใช้ deadline เดิม สีเหลืองเมื่อเหลือไม่เกิน 5 นาที
- **ยกเลิกก่อนชำระ** พนักงานระบุเหตุผล ยกเลิก Session และบิลเป็น **CANCELLED** ปล่อยจุด ไม่มีรายรับ ไม่ลบ charges/audit/ประวัติ
- **ยกเลิกหลังรับเงิน** พนักงานส่งคำขอ ผู้จัดการอนุมัติพร้อมเหตุผลและยอดคืนตามนโยบาย บันทึก refund อ้าง Transaction รับเงินเดิม ไม่ลบการขาย ไม่คืนซ้ำ การคืนเงินทั้งบิลไม่รับสินค้าคืนเข้าสต๊อกอัตโนมัติ หากคืนเงินไปแล้วห้ามใช้ปุ่มคืนสินค้าเพื่อคืนเงินซ้ำ; ของที่รับคืนภายหลังให้ผู้จัดการปรับ stock พร้อมเหตุผล
- **กู้คืนคิวที่จบผิด** ผู้จัดการระบุเหตุผลและจุดว่าง ใช้ Session/บิล/deadline เดิม ไม่รับเงินใหม่ ไม่รีเซ็ตเวลา หมดแล้วก็แสดงหมดเวลา

พนักงานเปิด–ปิดไฟด้วยมือทั้งหมด ไม่มีคำสั่งควบคุมอุปกรณ์ไฟฟ้า

## POS เดี่ยวและการจัดการสินค้าเดิม

ยังมี POS สำหรับขายสินค้าโดยไม่เปิด Station: ใส่ตะกร้าแล้วรับเงินสด/QR สร้างบิลสินค้า PAID แยกหนึ่งบิล (`session_id: null`) ไม่ใช่บิลหลักเพิ่มของ Session หากต้องการขายรวมบริการ ต้องใช้ **เพิ่มสินค้า** ที่ Station นั้น

- ผู้จัดการเพิ่ม/แก้ SKU, ชื่อ, หมวด, บาร์โค้ด, ทุน, ขาย และเปิด/ปิดขาย
- พนักงานรับเข้าได้ ผู้จัดการปรับ stock เพิ่ม/ลดพร้อมเหตุผลได้ Stock ติดลบไม่ได้
- ผู้จัดการคืนสินค้าอ้างรายการขายเดิม จำกัดทั้งจำนวนและยอดที่ยังไม่คืน เลือก restock ได้ คืนราคาขณะขายและสร้าง refund/movement/audit ไม่ลบ sale เดิม
- POS ตะกร้ากลางยังเป็นหนึ่งชุดร่วมกัน สินค้าปิดขายขายไม่ได้ ราคา POS เปลี่ยนหลังใส่ตะกร้าต้องนำออกแล้วเพิ่มใหม่ ส่วนบิล Station ใช้ราคาที่ตกลงตอนเพิ่มเข้าบิล

## รายงานและหลักการนับรายได้

เลือกวัน/เดือน/ช่วงวันที่ตาม **Asia/Bangkok** (รวมวันที่สุดท้าย) มีทั้งรายการรับ–คืนเงิน และรายงานบิล/CSV:

- Bill ID, Session ID, Station, เวลาเริ่ม/จบ/ใช้งาน, รายการบริการ/สินค้า, ยอดบริการ/สินค้า/รวม
- เงินสด/QR, เวลาชำระ, พนักงาน, Payment/Transaction IDs และสถานะ **PAID / UNPAID / CANCELLED / REFUNDED**
- รายรับจากบิลที่ชำระสำเร็จเท่านั้น ไม่มีการรวม charges ของ UNPAID/CANCELLED ที่ยังไม่รับเงิน
- Payment ที่เคยรับแล้วไม่หายจากประวัติเมื่อคืนเงินหรือ VOID: คงยอดรับเดิมแล้วหัก refund ตามวันที่คืนจริง บิลที่คืนบางส่วนใช้สถานะ REFUNDED พร้อมยอดคืนและยอดสุทธิ ไม่ใช่ลบยอดรับเดิมทั้งหมด
- แยกบริการ 20 บาท ต่อเวลา สินค้า รายการคืน ยอดสุทธิ เงินสด/QR และข้อมูลเก่าไม่ทราบหมวด/ช่องทาง
- รายงาน Session ใช้กลุ่มที่เริ่มในช่วงวันที่ พร้อมจำนวนย้ายและเส้นทางจุด ส่วนรายงานบิลเลือกบิลที่เปิด/ชำระ/มีธุรกรรมในช่วงวันที่ แสดงสถานะและยอดสะสมของบิล ณ ปัจจุบัน รายรับสรุปเลือกตามเวลาธุรกรรมจริง จึงอาจมีคิวเก่าที่มาชำระวันนี้หรือคืนวันนี้

CSV ธุรกรรมใช้เวลารายการรับ/คืน ส่วน CSV บิลมีข้อมูลข้างต้นครบพร้อมป้ายข้อมูลทดสอบ ไม่ใช่ใบกำกับภาษี

## อัปเดตและรักษาข้อมูลเดิม

1. รอคำสั่งรับ/คืนเงินรุ่นเก่าให้ทราบผลก่อนอัปเดต กดสำรอง JSON และปิด server เก่า
2. แตกโค้ดใหม่คนละโฟลเดอร์ เก็บโฟลเดอร์เดิมไว้ หากต้องใช้ข้อมูล server เดิม ให้คัดลอก `.data` **ทั้งโฟลเดอร์หลังปิด server แล้ว** ห้ามคัดลอก SQLite เดี่ยวขณะทำงาน และห้ามเปิดสำเนาสองชุดเป็นระบบหลักพร้อมกัน
3. เมื่อเปิดใหม่ ระบบอัปเกรด v2/v3/v4 → v5 ใน transaction เก็บ snapshot รุ่นเดิมใน `schemaArchives` ไม่ลบ transactions/receipts/audit ไม่เริ่มเวลาใหม่ และไม่สร้างรายรับย้อนหลัง
4. บิล Prepaid ที่จ่ายแล้วคง PAID และยอดเดิม ไม่เรียกเก็บ 20 บาทซ้ำ บิลเก่าที่มีรับเงินบางส่วนและยังค้างต้องให้ผู้จัดการตรวจ/คืนเงิน/VOID ตามประวัติ ไม่ใช้รับเต็มซ้ำ รุ่นนี้ไม่รองรับเก็บยอดเพิ่มของบิลที่รับเงินแล้ว
5. Local Demo ใช้ key `neeb20:demo:v5` นำเข้าจาก v4/v3/v2/v1 ใน origin เดียวกัน ไม่ลบ key เก่า ไม่ย้ายข้าม path/เครื่องหรือเข้า server อัตโนมัติ มี `legacyArchive` สำหรับ v1 ที่ไม่อาจสร้างรายละเอียดรับเงินจริงย้อนหลังได้

ปุ่มสำรองข้อมูลส่งออก state ครบ ไม่มีปุ่มล้างประวัติ ยังไม่มีหน้ากู้ฐานจาก JSON อัตโนมัติ

## ข้อจำกัดและความปลอดภัย

ข้อมูล Server Demo เก็บถาวรใน `.data/demo.sqlite` ไม่ใช้ Local Storage เป็นฐานรายได้/stock ใช้ SQLite `BEGIN IMMEDIATE`, revision, idempotency และตรวจ Session/จุด/สต๊อกในขณะบันทึก คำสั่งเก่าตอบ conflict ให้เปิดตรวจใหม่ ไม่ retry ด้วย revision ใหม่โดยไม่ยืนยัน

UI เก็บเฉพาะคำสั่งค้างใน sessionStorage เมื่อผลเครือข่ายไม่แน่นอนให้ retry ID/payload เดิม หลัง refresh ตรวจคำสั่งที่ server บันทึกแล้วก่อน ไม่บันทึกรับเงินใหม่ทันที

**ยังเป็น Demo:** เลือกบทบาทพนักงาน/ผู้จัดการได้ ไม่ใช่ authentication จริง แม้ server ตรวจบทบาท ห้ามใช้รับเงินจริงหรือข้อมูลลูกค้าจริง ต้องเพิ่ม login/manager approval ที่พิสูจน์ตัวตน, HTTPS, schema production, backup/restore และทดสอบอุปกรณ์ก่อนใช้จริง QR เป็นการระบุช่องทางที่พนักงานตรวจเอง ไม่เชื่อมธนาคาร ไม่มีรหัสผ่าน/ข้อมูลลับฝังในโค้ด

นาฬิกานับจาก deadline จริง ใช้ server offset ใน UI แต่ยังต้องทดสอบ drift/latency บนเครื่องจริง หน้าเว็บพัก/ล็อกจอไม่รับประกันแจ้งเตือน

## ทดลองหลายอุปกรณ์และไฟล์ Local Demo

หากใช้ LAN ที่ไว้ใจ เปิด PowerShell `$env:HOST="0.0.0.0"` แล้ว `npm start` ทุกอุปกรณ์ต้องเข้า `http://<IP เครื่อง server>:3000` ตัวเดียวกัน อนุญาต firewall เฉพาะ private network เมื่อจำเป็น ห้ามเปิดพอร์ต Demo ออกอินเทอร์เน็ต

`NEEB20-DEMO.html` ใช้ทดลอง UI อย่างเดียว มีป้าย LOCAL DEMO ไม่ใช่ฐานรายได้/stock ของร้าน ต้องใช้ Server Demo สำหรับข้อมูลถาวร/หลายเครื่อง การเปิด file:// ขึ้นกับ browser และนโยบายองค์กร ถ้าบล็อกให้ใช้ server ไม่ปิดระบบความปลอดภัย

## ทดสอบ

```powershell
npm test
npm run build:demo
```

73 Node tests ครอบคลุมตัวอย่างบิล 64 บาท ย้ายบิล 49 บาท timer/refresh บล็อกจบคิว UNPAID รายรับไม่ซ้ำ จ่ายพร้อมกันสองเครื่อง stock ไม่พอ rollback ทั้งบิล ยกเลิกก่อนจ่าย/คืนหลังจ่าย กู้คืน รายงาน/CSV migration และ restart SQLite รวมสูตรกำไร snapshots ค่าคอมไม่หักซ้ำ การคืนต้นทุน สิทธิ์ API และข้อมูลย้อนหลัง

UI integration แบบ optional สำหรับผู้พัฒนา:

```powershell
npm install --no-save --package-lock=false --ignore-scripts playwright
npx playwright install chromium
npm run test:browser
```

ทดสอบ Chromium ด้วยฐาน in-memory แยกจาก `.data` ครอบคลุมกดเริ่ม/ต่อเวลาทันที บิล 64 และจ่ายซ้ำ ย้ายพร้อมบิล การจบก่อนจ่ายพาไปคิดเงิน การคืนเงิน สินค้า/stock รายงานทั้ง 4 สถานะ CSV และ pending command หลัง refresh สามารถใช้ `NEEB20_CHROMIUM`/`NEEB20_PLAYWRIGHT_MODULE` หากติดตั้งเครื่องมืออีกตำแหน่ง ยังไม่ได้ทดสอบ Windows/Safari/iPad หรืออุปกรณ์จริง
