# หนีบ20 — NEEB20 Management System

ต้นแบบภาษาไทยสำหรับ 12 Stations และ POS **ข้อมูลทดสอบเท่านั้น ไม่รับ/คืนเงินจริง ไม่เชื่อมไฟฟ้าหรือสต๊อกจริง** รุ่นนี้เพิ่มการย้ายจุด อนุมัติยกเลิก กู้คืนคิว Audit Log และป้องกันคำสั่งซ้ำ โดยคงราคา/เวลาและ POS เดิม

## เปิดบน Windows — แนะนำโหมด Server Demo

1. ดาวน์โหลด ZIP ของสาขา `neeb20/prototype-demo` จาก GitHub แล้ว **Extract All / แยกทั้งหมด** ก่อนเปิด อย่าเปิดจากใน ZIP และอย่าแตกทับโฟลเดอร์รุ่นเก่าที่มีข้อมูล ให้เก็บรุ่นเก่าไว้สำรอง
2. ติดตั้ง **Node.js 24 LTS** จาก https://nodejs.org (รองรับขั้นต่ำ 22.13 เพราะใช้ SQLite ใน Node built-in)
3. ดับเบิลคลิก `START-NEEB20.cmd` เปิดหน้าต่างนี้ค้างไว้ รอข้อความ `NEEB20 SERVER DEMO`
4. เปิด Edge หรือ Chrome พิมพ์ `http://127.0.0.1:3000` จะแสดง Station 12 จุด และ POS อยู่ด้านล่าง
5. ปิดด้วย Ctrl+C ในหน้าต่างเซิร์ฟเวอร์ อย่าลบโฟลเดอร์ `.data` เพราะเก็บฐานข้อมูลทดสอบ

หรือเปิด Terminal ในโฟลเดอร์ที่มี `package.json` แล้วรัน:

```powershell
node --version
npm start
```

ไม่ต้อง `npm install` สำหรับแอปหรือ Node tests ไม่มี application dependency ภายนอก หากมีเซิร์ฟเวอร์รุ่นเก่าทำงานอยู่ ให้ Ctrl+C ปิดก่อนเปิดรุ่นนี้ ถ้าพอร์ตชน: `$env:PORT=3001` แล้ว `npm start` จากนั้นเปิดพอร์ต 3001 แทน

**Cloud กับ Windows เป็นคนละเครื่อง** การรันใน Cloud ไม่ทำให้ localhost บน Windows เปิดได้ และเซสชัน Cloud นี้ไม่มีช่องทางเผยแพร่ public Live Preview โดยอัตโนมัติ ต้องดาวน์โหลดโค้ดและรันบนเครื่องตามขั้นตอนข้างต้น

### ทดลองสองอุปกรณ์บนเครือข่ายเดียวกัน

ค่าเริ่มต้นผูกกับ `127.0.0.1` เพื่อใช้เครื่องเดียว สำหรับทดสอบ LAN ที่ไว้ใจเท่านั้น เปิด PowerShell แล้ว:

```powershell
$env:HOST="0.0.0.0"
npm start
```

เปิด `http://<IP คอมพิวเตอร์ที่รันเซิร์ฟเวอร์>:3000` บนทั้งสองเครื่อง/iPad และอนุญาต Windows Firewall เฉพาะ private network หากจำเป็น **ต้องเข้าเซิร์ฟเวอร์ตัวเดียวกัน** ห้ามเปิดพอร์ตออกอินเทอร์เน็ต บทบาททดสอบไม่ใช่ระบบล็อกอิน ใครที่เข้าได้เลือกผู้จัดการได้ ห้ามใช้งานเงินจริง

Server Demo เก็บใน `.data/demo.sqlite` ใช้ SQLite transaction + revision + idempotency key เพื่อตรวจสถานะล่าสุดในขณะบันทึก รองรับการทดสอบคำสั่งชนกันบนฐานเดียวกัน ไม่ใช่การเชื่อม localStorage ระหว่างเครื่อง ตะกร้า POS เป็นตะกร้ากลางร่วมกันหนึ่งชุดในรุ่นนี้ คำสั่งที่ชนกันจะถูกปฏิเสธให้ตรวจสอบใหม่ ไม่ retry โดยยอมรับข้อมูลใหม่ให้อัตโนมัติ

## ไฟล์เดียว ไม่ติดตั้ง Node.js — Local Demo

คลิกขวา `NEEB20-DEMO.html` → Open with → Edge หรือ Chrome ดูข้อความ **LOCAL DEMO** ด้านบน ข้อมูลอยู่ในเบราว์เซอร์เท่านั้น **ไม่รองรับหลายอุปกรณ์** การเปิด `file://` และการจัดเก็บขึ้นกับ browser/นโยบายองค์กร ถ้าถูกบล็อกให้ใช้ Server Demo อย่าปิดระบบความปลอดภัย การย้าย/เปลี่ยนชื่อไฟล์หรือเปลี่ยนเบราว์เซอร์อาจทำให้ไม่เห็นข้อมูลเดิม

Local Demo อ่าน key `neeb20:demo:v2` ถ้ายังไม่มี จะนำเข้าคิว/เวลาสิ้นสุด สินค้า และตะกร้าที่ยังค้างจาก `neeb20:demo:v1` ใน origin เดียวกัน พร้อมเก็บข้อมูลเดิมทั้งหมดใน `legacyArchive` และ **ไม่ลบ key v1** บิลรับเงินรุ่นเก่าอยู่ใน archive ไม่ถูกสร้างเป็นธุรกรรมรับเงินใหม่หรือรวมซ้ำในสรุปรุ่นนี้ หากเปิดไฟล์จาก path ใหม่แล้วไม่พบข้อมูลเก่า ให้กลับไปใช้ไฟล์/path เดิมก่อน ห้ามคิดว่าข้อมูลเดิมถูกโอนข้าม path/เครื่องให้อัตโนมัติ

ฐานข้อมูล Server Demo แยกจาก Local Demo ไม่ได้นำเข้าข้อมูลจาก browser อัตโนมัติ มีปุ่ม **สำรองข้อมูลทดสอบ** ส่งออก JSON ครบทั้ง Session, บิล, ธุรกรรม, คำสั่ง, Audit Log และ legacyArchive ยังไม่มีหน้ากู้ฐานข้อมูลจาก JSON

## การทำงานรุ่นนี้

- เริ่มบริการ: ยืนยันหมายเลขจุดก่อน สร้าง `session_id` และบิลอ้างอิงเฉพาะ 20 บาท/25 นาที **ยังไม่มีธุรกรรมรับเงิน**
- ย้ายจุด / แก้ไขจุดที่เริ่มผิด: แสดงจุดเดิม จุดว่าง เวลาคงเหลือ ค่าบริการ และเหตุผล ย้าย Session เดิม บิลเดิม ไม่เปลี่ยนกำหนดสิ้นสุด ไม่เพิ่มยอดขาย ตรวจจุดว่างซ้ำในธุรกรรม
- ต่อเวลา: ยืนยันเพิ่ม 5 นาที/5 บาท ใช้ Session/บิลเดิม ถ้าบิลชำระแล้วสร้าง charge เรียกเก็บเพิ่มเชื่อมบิลเดิม แสดงยอดรับแล้วและยอดค้างแยกกัน ต้องกด “เรียกเก็บเงิน” เพื่อส่งยอดค้างเข้าตะกร้า
- จบคิว: หน้าต่างแสดง Station, Session ID เต็ม, เวลาเริ่ม/สิ้นสุด ค่าบริการ และการเงิน ปุ่มถูกล็อกระหว่างบันทึก จบคิวปล่อยจุดและใส่เฉพาะยอดค้างในตะกร้า **ไม่รับเงิน ไม่สร้างบิลใหม่**
- จบผิด: เลือกผู้จัดการทดสอบ ใช้ “กู้คืนคิว” ในรายการคิว ต้องมีจุดว่างและเหตุผล ใช้ Session/บิลเดิม ถ้าเวลาหมดแล้วจะแสดงหมดเวลา ไม่รีเซ็ต 25 นาที
- เริ่มโดยไม่มีลูกค้า: ส่งคำขอยกเลิกพร้อมเหตุผล ผู้จัดการอนุมัติอีกขั้น ไม่ลบประวัติ และไม่คืนเงินอัตโนมัติ หากรับเงินแล้วให้ทำคำสั่งคืนเงินแยก
- สถานะบริการแยกจากการเงิน: กำลังใช้งาน/หมดเวลา/จบคิว/ยกเลิก ส่วนจุดไม่มีคิวแสดงว่าง การเงินแสดงยังไม่ชำระ/ชำระแล้ว/คืนบางส่วน/คืนเต็ม/ยกเลิกก่อนรับเงิน พร้อมยอดรับแล้ว คืนแล้ว และค้าง
- รับเงินทดสอบ: กดปุ่มยืนยันบิล POS เท่านั้น จึงสร้าง receipt และ payment transactions ที่มีรหัสเฉพาะ และปรับเฉพาะสต๊อกจำลอง คำสั่งเดิมส่งซ้ำจะคืนผลเดิม ไม่เพิ่มยอด/ตัด stock ซ้ำ
- คืนเงินทดสอบ: ผู้จัดการระบุจำนวนและเหตุผล จำกัดไม่เกินยอดรับสุทธิของบิลบริการ เก็บรายการ refund ใหม่ ไม่ลบ/แก้ payment หรือ receipt เดิม การคืนเงินไม่เปิดหนี้เดิมให้เรียกเก็บซ้ำอัตโนมัติ ไม่มีการคืนสินค้าหรือคืนสต๊อกในรอบนี้
- สรุปยอด: รวม `payment - refund` จาก transactions ทดสอบเท่านั้น ไม่ได้นับจาก start/move/finish และไม่รวมบิลรับแล้วจาก archive รุ่นเก่า
- Audit: เริ่ม/ย้าย/ต่อเวลา/จบ/คำขอยกเลิก/อนุมัติ/กู้คืน/รับ/คืนเงิน มีเวลา ผู้ดำเนินการ Session before/after เหตุผล และ command ID เก็บทั้งหมด แสดงล่าสุด 50 เหตุการณ์พร้อมประวัติรายคิวและปุ่มสำรอง ไม่มีปุ่มล้างประวัติในรุ่นนี้

หมดเวลาไม่ปิดคิวเอง พนักงานเปิด–ปิดไฟด้วยมือ สีเหลืองเมื่อเหลือไม่เกิน 5 นาที สีแดงเมื่อหมด ไม่มีเสียง/push การต่อเวลาจาก deadline เดิมอาจยังหมดเวลา ถ้ากดต่อหลังเลยกำหนดไปนาน

## สิทธิ์และข้อจำกัดก่อนใช้จริง

บทบาท staff/manager ถูกตรวจใน command handler ฝั่งเซิร์ฟเวอร์ แต่ **การเลือกพนักงานในหน้าเว็บเป็นการจำลองและไม่มี authentication** จึงยังกันการปลอมตัวเป็นผู้จัดการจริงไม่ได้ ยังไม่พร้อมใช้รับเงินจริง ต้องเพิ่ม login/session ที่ตรวจตัวตนจริง ให้ server ผูก actor กับผู้ล็อกอินเอง ตัดสิทธิ์ client ที่ส่ง actorId เอง และทดสอบสิทธิ์จริงก่อนใช้งาน

Server ใช้เวลาของเครื่องเซิร์ฟเวอร์บันทึกคำสั่ง ส่วนการแสดงเวลาคงเหลือยังอิงนาฬิกาเครื่องผู้ใช้ ต้องตั้งนาฬิกาเครื่องให้ตรง หน้าเว็บพัก/ปิดไม่รับประกันแจ้งเตือน การจำลองหน้าจอบน Chromium ไม่แทนการทดสอบ Safari/iPad จริง

SQLite รุ่นนี้เก็บ state JSON หนึ่งแถวภายใต้ transaction เหมาะฐานทดสอบขนาดเล็ก ฐานข้อมูลและข้อมูลเป็น demo เท่านั้น ก่อน production ต้องเพิ่ม schema/constraints แบบ normalized, authentication, backup/restore ที่ทดสอบกู้ได้, deployment HTTPS และการตรวจสอบความสมบูรณ์ของข้อมูล ห้ามใช้ฐาน/โฟลเดอร์นี้ปะปนข้อมูลจริง ดู [แผนฐานข้อมูลและความปลอดภัย](docs/architecture.md)

## ทดสอบ

```powershell
npm test
npm run build:demo
```

Node tests ครอบคลุม 9 ข้อที่ร้องขอ รวมถึงย้ายไปจุดไม่ว่าง, คำสั่งซ้ำ, ยกเลิกพร้อมประวัติ/สิทธิ์, กู้คืน, ค่าต่อเวลา, สองอุปกรณ์แข่งจองจุด, serialize/refresh deadline และเพิ่มกรณี refund, stock rollback, legacy migration, restart SQLite, HTTP origin/body validation

ทดสอบ UI อัตโนมัติแบบ optional สำหรับผู้พัฒนา (ไม่จำเป็นต่อการเปิดแอป):

```powershell
npm install --no-save --package-lock=false --ignore-scripts playwright
npx playwright install chromium
npm run test:browser
```

Browser test ใช้ฐาน SQLite ในหน่วยความจำเฉพาะการทดสอบ ไม่ใช้ `.data/demo.sqlite` ตรวจ 12 จุด/หมดเวลา ย้าย/รีเฟรช ต่อเวลา กดจบซ้ำ POS 83 บาท กู้คืนบิลชำระแล้ว เรียกเพิ่ม 5 บาท อนุมัติยกเลิก คำสั่งเก่าจากสอง browser contexts บาร์โค้ด responsive และ migration Local Demo สามารถใช้ Chromium ที่ติดตั้งไว้ผ่าน `NEEB20_CHROMIUM` แทนดาวน์โหลด และกำหนด `NEEB20_PLAYWRIGHT_MODULE` เป็น module path หากติดตั้งเครื่องมือไว้นอกโครงการ

### ทดสอบด้วยมือ

1. เริ่มจุด 01 ย้ายไป 03 พร้อมเหตุผล ตรวจ Session/บิล/deadline เดิมและจุด 01 ว่าง รีเฟรชแล้วเวลาไม่เริ่มใหม่
2. เริ่มจุด 02 แล้วลองย้าย 03 ไป 02 ต้องไม่มีให้เลือก และถ้าเปิด modal ค้างไว้แล้วอีกอุปกรณ์เริ่มจุดปลายทาง คำสั่งเดิมต้องถูกปฏิเสธ
3. ต่อเวลาให้จุด 03 เป็น 25 บาท แล้วจบคิว ตรวจยังไม่มียอดรับเงิน เพิ่มหวีทดสอบ 2 ชิ้น รวม 83 บาท ยืนยันบิลแล้วจึงแสดงยอดรับเงินและสต๊อกหวี 18
4. เลือกผู้จัดการทดสอบ กู้คืนคิว 03 พร้อมเหตุผล ตรวจบิลเดิม ไม่มีรับเงินซ้ำ ต่อเวลาเพิ่มแล้วเรียกเก็บควรค้างเพิ่มเพียง 5 บาท
5. พนักงานขอยกเลิกจุด 02 พร้อมเหตุผล เลือกผู้จัดการอนุมัติ ตรวจประวัติยังอยู่ ถ้ารับเงินแล้ว ตรวจว่าไม่มี refund จนกว่าจะบันทึกคืนเงินแยก
6. เปิดสอง browser/อุปกรณ์ไป server เดียวกัน เปิด modal เริ่มจุดเดียวกันพร้อมกัน เครื่องแรกสำเร็จ เครื่องหลังต้องแจ้งข้อมูลเปลี่ยนและไม่สร้างคิวที่สอง
7. สำรอง JSON ตรวจ audit/ธุรกรรมครบ ปิด/เปิด server ใหม่ ข้อมูลเดิมต้องอยู่ ห้ามลบฐานข้อมูลเพื่อแก้ปัญหา

## ไฟล์หลัก

- `src/domain.js` — Session, บิล, ธุรกรรม, audit, สิทธิ์, idempotency, migration
- `src/app.js`, `index.html`, `src/style.css` — หน้าจอเดิมและหน้าต่างยืนยัน/ย้าย/อนุมัติ/กู้คืน
- `server.js`, `server/store.js` — HTTP API และ SQLite transaction
- `test/domain.test.js`, `test/server.test.js` — ทดสอบกฎและคำสั่งพร้อมกัน
- `scripts/browser-test.mjs` — ทดสอบ Chromium แบบ optional
- `scripts/build-demo.js`, `NEEB20-DEMO.html` — สร้าง/เปิดไฟล์ Local Demo รวมในไฟล์เดียว
- `START-NEEB20.cmd` — ตัวช่วยเปิดบน Windows

โมดูลจองสระ100 พนักงานจริง/ค่าคอมมิชชัน อุปกรณ์รับชำระเงิน เครื่องพิมพ์ และลิ้นชักเงินยังไม่อยู่ในรอบนี้ ไม่มีรหัสผ่านหรือข้อมูลลับฝังในโค้ด
